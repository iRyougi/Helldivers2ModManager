## 2. Mod Conflict Detection on Deploy

**Definition of conflict:** Two or more enabled mods contain patch files that share the same 16-character hexadecimal prefix (e.g., `1a2b3c4d5e6f7890`). These mods both attempt to modify the same game asset. The later mod in load order will overwrite the earlier one.

**Trigger:** When the user clicks "Deploy", before actual file deployment begins.

**New model:** `ConflictInfo` record in `Models/`:
```csharp
record ConflictInfo(string PatchPrefix, ModData[] ConflictingMods);
```

**New method on `ModService`:**
```csharp
public ConflictInfo[] DetectConflicts(Guid[] enabledModGuids)
```
- For each enabled mod, scan its directories for files matching `GetPatchFileRegex()`.
- Group by the 16-char prefix.
- Return prefixes where > 1 mod contributes files.

**In `DashboardPageViewModel.Deploy()`:**
- Call `DetectConflicts(guids)` before `DeployAsync`.
- If conflicts found: show an informational message box listing:
  - Each conflicting prefix
  - Which mods conflict, in load order
  - "Later mods override earlier ones — conflicts are normal if intentional"
  - [Continue Deploy] [Cancel]
- If user cancels: abort deploy.
- If user continues: proceed normally.

**Localization keys added:**
- `Message.ConflictDetectedTitle`
- `Message.ConflictDetectedPrefix` (header)
- `Message.ConflictDetectedItem` (per-conflict format)
- `Message.ConflictDetectedFootnote`
- `Message.ConflictDetectedContinue` / `Message.ConflictDetectedCancel`

**Files changed:**
- `Models/ConflictInfo.cs` (new)
- `Services/ModService.cs` — add `DetectConflicts()`
- `ViewModels/DashboardPageViewModel.cs` — modify `Deploy()`
- `Services/LocalizationService.cs` — add new keys to both `en` and `zh-cn`

## 3. Wrong-Mod Update Warning

**Trigger:** In `DashboardPageViewModel.Update()`, after user selects archive file, before calling `_modService.UpdateModFromArchiveAsync()`.

**Logic:**
1. Extract and parse the manifest from the selected archive into a temp directory (read-only).
2. Compare new manifest's `Guid` with `modVm.Guid`.
3. If different: show warning dialog:
   - "The selected file appears to be a different mod."
   - "Original: [modVm.DisplayName] (GUID: ...)"
   - "Selected: [newManifest.Name] (GUID: ...)"
   - [Continue Anyway] [Cancel]
4. If user cancels: clean up temp dir, abort.
5. If user continues: proceed with update as normal.

**Note:** A lightweight archive peek is needed — extract to temp, read manifest, then either proceed or clean up.

**Localization keys added:**
- `Message.UpdateGuidMismatchTitle`
- `Message.UpdateGuidMismatchMessage`

**Files changed:**
- `ViewModels/DashboardPageViewModel.cs` — modify `Update()`
- `Services/LocalizationService.cs` — add new keys

## 5. Single Instance Enforcement

**Mechanism:** Named Mutex in `App.xaml.cs`.

**Logic in `App.OnStartup()`:**
1. Try to acquire a named mutex `"Global\\HD2ModManager_SingleInstance"`.
2. If already owned by another process: find the existing window and bring it to front using `Win32 SetForegroundWindow` / `ShowWindow`, then `Application.Current.Shutdown()`.
3. If not owned: continue normal startup, release mutex on `OnExit`.

**Win32 approach:**
- Use `Process.GetProcessesByName()` to find the other instance.
- Get its main window handle via `process.MainWindowHandle`.
- Call `NativeMethods.SetForegroundWindow(hwnd)` and `NativeMethods.ShowWindow(hwnd, SW_RESTORE)`.

**Files changed:**
- `App.xaml.cs` — add mutex logic in `OnStartup`, release in `OnExit`
- `NativeMethods.cs` (new) — P/Invoke declarations for `SetForegroundWindow`, `ShowWindow`

## Localization Strategy

All new string keys are added to `LocalizationService.CreateDefaultLanguageFilesAsync()` in both `enTranslations` and `zhCnTranslations` dictionaries. The version number `CurrentTranslationVersion` is incremented from 3 → 4 so existing language files auto-update.
